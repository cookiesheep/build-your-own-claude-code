## ★ 已决：选择路线 A（纯变体文件机制）

**决策**：Lab 1-3 全部使用变体文件机制（`-labN` 后缀），和 Lab 0 一致。

**渐进式能力解锁**（核心设计）：
- Lab 0: Claude Code 能启动但**连对话都做不到**（API 调用被挖空）
- Lab 1: 学习者修好 API 调用 → Agent 能对话但**不能用工具**

**反馈机制**：全程依靠在终端里直接观察 Claude Code 的行为变化。不需要 Mock LLM、不需要 stdout 断言、不需要测试框架。

## 一、当前已确认的机制

### 变体文件机制（已在用）

学习者通过 `-labN` 后缀的变体文件修改 claude-code-diy 源码：

```
claude-code-diy/src/
  components/LogoV2/
    Clawd.tsx          ← 原始文件（不动）
    Clawd-lab0.tsx     ← Lab 0 变体（学习者创建/修改）

build.mjs --lab=0
  → discoverLabSwaps() 发现 *-lab0.* 文件
  → 编译时替换原始文件的产物
  → 整个 416K 行系统一起编译
```

- Lab 0 已按此机制开发完成（6 个变体文件）
- PoC 已验证：`query-lab.ts`（~190 行）替换 `query.ts`（1,729 行）可行

## 二、核心待决问题

### 问题 1：Lab 1-3 用什么机制？

**两条路线**：

**路线 A：继续用变体文件机制**
- Lab 1: `query-lab1.ts` 替换 `query.ts`，学习者实现简化版 query 函数
- Lab 2: 在 Lab 1 基础上加工具执行逻辑
- Lab 3: 在 Lab 2 基础上加 while(true) 循环
- 优点：和 Lab 0 机制一致，已有 PoC 验证
- 缺点：学习者需要理解 416K 系统中 query.ts 的依赖链，入门门槛高

**路线 B：独立模块 + 依赖注入（LAB_DESIGN.md 建议）**
- Lab 1-3 在 `labs/lab-XX/` 下创建独立 TypeScript 模块
- 通过接口接收 LLMClient、ToolExecutor 等依赖
- 测试用 Mock，TUI 集成时才连接 claude-code-diy
- 优点：学习者代码独立可测，入门门槛低
- 缺点：和 Lab 0 的变体文件机制不一致，需要额外设计 bridge 代码

**路线 C：混合方案**
- Lab 0 用变体文件（品牌定制，不需要深度理解架构）
- Lab 1-3 用独立模块（核心编程，需要清晰的学习路径）
- 需要：设计独立模块如何与 claude-code-diy 的 query.ts 对接

**当前状态**：✅ **路线 A 已选定**。纯变体文件机制，Lab 0-3 全部使用 `-labN` 后缀。

### 问题 2：评测怎么做？

**已决：编译验证 + TUI 体验**

| 评测层次 | 方式 | 状态 |
|---------|------|------|
| Level 1：构建验证 | `build.mjs --lab=N` → exit code 0？ | ✅ 已有（后端 `POST /api/submit`）|
| Level 3：TUI 体验 | 编译成功 → ttyd 启动 → 学习者观察 Agent 行为 | ✅ 已有 |

**不需要**：Mock LLM Server、stdout 断言、黑盒测试框架。

**反馈 = 终端里直接看 Claude Code 的行为**：
- Lab 0 构建后：Agent 连对话都做不到 → 学习者看到"坏了"
- Lab 1 构建后：Agent 能对话但不能用工具 → 学习者看到"能说话了"
- Lab 2 构建后：Agent 能用工具但用一次就停 → 学习者看到"能动手了"
- Lab 3 构建后：Agent 自主多轮调用工具 → WOW!
