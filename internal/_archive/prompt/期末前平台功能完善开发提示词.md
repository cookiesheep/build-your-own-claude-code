## 项目背景

### 项目定位

BYOCC 是一个基于真实 Claude Code 源码的渐进式教学项目。学习者通过 6 个 Lab 逐步实现 Agent Harness 的核心模块。

### 平台架构

```
Frontend (Next.js 16)
  ├── /login — 登录页
  ├── /platform — Lab 列表首页
  └── /lab/[id] — Lab 工作区（Monaco Editor + xterm.js 终端 + 文档面板）

Backend (Express + SQLite)
  ├── /api/auth/* — 认证（匿名 + 密码登录）
  ├── /api/session — Docker 容器会话管理
  ├── /api/submit — 代码注入 + 构建触发
  ├── /api/progress — Lab 完成进度
  ├── /api/settings/* — API Key 管理（CRUD + 验证）
  ├── /api/llm-proxy — LLM 请求代理
  ├── /api/files — Lab 文件服务
  ├── /api/workspace — Workspace 持久化
  ├── /api/reset — 容器重置
  └── WS /api/terminal/:sessionId — ttyd WebSocket 代理

Infrastructure
  ├── Docker 容器（claude-code-diy 运行环境）
  ├── ttyd（终端 Web 化）
  ├── 华为云 Ubuntu 24.04 (16核 62GB)
  └── systemd 管理服务
```

### 当前用户系统

数据库 `users` 表已支持三种用户类型（`kind` 字段）：
- `anonymous` — 匿名用户（自动创建）
- `password` — 密码用户（通过 `server/src/scripts/create-user.ts` 手动创建）
- `github` — GitHub 用户（`github_id` 列已存在，但 OAuth 流程**尚未实现**）

**当前登录方式只有密码登录，没有注册功能。用户由管理员通过脚本创建。**

### 当前认证流程

```
1. 用户访问 /platform → AuthGuard 检查 /api/auth/me
2. 未登录 → 重定向到 /login?redirect=/platform
3. 用户输入用户名密码 → POST /api/auth/login → 设置 session cookie
4. 登录成功 → 重定向回原始页面
```

## 工作原则

1. **先读代码再建议** — 不要基于假设给方案，每个建议都要有代码依据
2. **渐进式改进** — 优先小步快跑，不要大重构
3. **安全第一** — 认证相关功能要特别注意安全
4. **具体到文件** — 不要说"修改认证相关文件"，要说"修改 server/src/routes/auth.ts，添加 getOAuthCallback 函数"
5. **考虑现有架构** — 所有方案必须兼容现有的 session cookie + SQLite 架构，不要引入不必要的新依赖
