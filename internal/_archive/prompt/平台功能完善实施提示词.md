## 一、项目上下文

### 项目是什么

BYOCC（Build Your Own Claude Code）是一个教学平台。学习者在浏览器里的 Monaco Editor 写代码，代码被注入 Docker 容器，编译后驱动真实的 Claude Code TUI 终端。核心体验是"自己的代码驱动真实 TUI"。

### 目录结构

```
build-your-own-claude-code/
├── server/                 # Express 后端（TypeScript, ESM）
│   ├── src/
│   │   ├── index.ts        # 入口，路由注册，CORS，JSON body
│   │   ├── db/database.ts  # SQLite + better-sqlite3，7 张表
│   │   ├── routes/         # API 路由（auth, session, environment, submit, progress, workspace, files, settings, llm-proxy, reset）
│   │   ├── services/       # 业务逻辑（container-manager, container-cleanup, auth-token, session-cookie, encryption, ws-proxy）
│   │   ├── middleware/      # auth 中间件，rate-limit
│   │   └── scripts/        # CLI 工具（create-user, cleanup-containers）
│   ├── package.json
│   └── tsconfig.json
├── platform/               # Next.js 16 前端
│   ├── src/
│   │   ├── app/            # 路由（/, /login, /platform, /lab/[id]）
│   │   ├── components/     # UI 组件（LabLayout, LabRightArea, CodeEditor, Terminal, DocsPanel, FileTree, AuthGuard, Navbar）
│   │   └── lib/            # 客户端库（api.ts, auth.ts, settings.ts, labs.ts, file-reader.ts）
│   ├── package.json
│   └── CLAUDE.md           # ⚠️ 必读："This is NOT the Next.js you know"
├── infrastructure/         # Dockerfile.lab, cloudflared-config.yml
├── CLAUDE.md               # 项目说明，必读
└── HANDOFF.md              # 完整项目交接文档
```

### 技术栈

- **后端**：Express + better-sqlite3（同步 API）+ Docker（dockerode）
- **前端**：Next.js 16 + React + TailwindCSS + Monaco Editor + xterm.js
- **构建**：后端 `tsdown`，前端 `next build`
- **认证**：匿名用户用 HMAC token（Bearer），密码/GitHub 用户用 JWT cookie（httpOnly）
- **TypeScript**：strict mode，ESM 模块（`import/export`，非 `require`）

### 认证架构（关键！）

```
匿名用户：localStorage 存 Bearer token → Authorization header → verifyUserToken()
密码/GitHub 用户：httpOnly cookie (byocc_session) → JWT 验证 → getSessionUserFromRequest()

getOptionalAuthUser() 逻辑（middleware/auth.ts:34-51）：
  1. 先查 cookie → 有就返回（密码/GitHub 用户走这条路）
  2. 再查 Bearer token → 有就 verifyUserToken → 返回（匿名用户走这条路）
  3. 都没有 → null
```

### 容器架构

```
每个学习者的 session 对应一个 Docker 容器：
- 容器内跑 ttyd（Web 终端）+ claude-code-diy（学习者代码编译后的产物）
- container-manager.ts 管理 sessionContainers Map 和 sessionTokenCache Map
- container-cleanup.ts 后台定时清理过期容器
- ws-proxy.ts 代理 ttyd 的 WebSocket 连接
```

## 四、任务清单

### Task P0-1: 断线/错误自动重试（2h）

**问题**：`LabRightArea.tsx:164-186` 的 auto-save effect 只在 `saveState === "dirty"` 时触发。当 save 失败（网络断开），`saveState` 变成 `"error"` 后，effect 不再触发，用户的代码改动无法保存。

**当前代码**（`platform/src/components/LabRightArea.tsx:163-186`）：
```typescript
// Auto-save
useEffect(() => {
  if (saveState !== "dirty") return;  // ← 问题：error 状态不触发重试

  const timer = window.setTimeout(() => {
    const requestId = saveRequestIdRef.current + 1;
    saveRequestIdRef.current = requestId;
    setSaveState("saving");
    void saveWorkspace(lab.id, workspaceFiles)
      .then((workspace) => {
        if (saveRequestIdRef.current === requestId) {
          setLastSavedAt(workspace.updatedAt);
          setSaveState("saved");
        }
      })
      .catch(() => {
        if (saveRequestIdRef.current === requestId) {
          setSaveState("error");
        }
      });
  }, 1500);

  return () => { window.clearTimeout(timer); };
}, [lab.id, saveState, workspaceFiles]);
```

**修改方案**：

1. 将条件从 `if (saveState !== "dirty") return` 改为同时接受 `"error"` 状态
2. error 状态时用更长的延迟（5 秒而非 1.5 秒）重试
3. 依赖数组中 `saveState` 已存在，不需要额外修改

```typescript
// Auto-save
useEffect(() => {
  if (saveState !== "dirty" && saveState !== "error") return;

  const delay = saveState === "error" ? 5000 : 1500;
  const timer = window.setTimeout(() => {
    const requestId = saveRequestIdRef.current + 1;
    saveRequestIdRef.current = requestId;
    setSaveState("saving");
    void saveWorkspace(lab.id, workspaceFiles)
      .then((workspace) => {
        if (saveRequestIdRef.current === requestId) {
          setLastSavedAt(workspace.updatedAt);
          setSaveState("saved");
        }
      })
      .catch(() => {
        if (saveRequestIdRef.current === requestId) {
          setSaveState("error");
        }
      });
  }, delay);

  return () => { window.clearTimeout(timer); };
}, [lab.id, saveState, workspaceFiles]);
```

**验证**：
- `cd platform && npx tsc --noEmit --project tsconfig.json` 通过
- 手动测试：打开浏览器 DevTools → Network → Offline 模式 → 修改代码 → 观察 saveState 变化 → 恢复网络 → 确认自动重试成功

### Task P1-7: 并发容器创建竞态防护（2h）

**问题**：用户快速双击"启动环境"可能触发两次 `createContainer`，创建两个容器。第一个被第二个覆盖，成为孤儿容器，浪费 2GB 内存。

**修改方案**：

在 `server/src/services/container-manager.ts` 顶部添加互斥锁：

```typescript
// 容器创建互斥锁，防止同一 session 并发创建
const containerCreationLocks = new Map<string, Promise<void>>();
```

在 `createContainer` 函数入口加锁：

```typescript
export async function createContainer(sessionId: string, ...): Promise<CreateContainerResult> {
  // 等待同一 session 的上一次创建完成
  const existingLock = containerCreationLocks.get(sessionId);
  if (existingLock) {
    await existingLock;
  }

  const lockPromise = (async () => { /* 原有的 createContainer 逻辑 */ })();
  containerCreationLocks.set(sessionId, lockPromise);

  try {
    return await lockPromise;
  } finally {
    containerCreationLocks.delete(sessionId);
  }
}
```

**前端配合**：检查 `LabRightArea.tsx` 中启动按钮是否在请求期间被禁用。如果按钮有 `disabled={isLoading}` 属性，则前端已防护；否则需要添加。

**验证**：
- `cd server && npx tsc --noEmit` 通过
- 无法自动测试竞态，但可以确认类型正确

### Task P1-4: sessionTokenCache 内存泄漏修复（3h）

**问题（严重）**：`container-cleanup.ts:246-248` 回收容器时直接调用 `docker.getContainer().remove()`，绕过了 `container-manager.ts:574-603` 的 `removeContainer`。`removeContainer` 的 `finally` 块（597-602 行）负责清理 `sessionTokenCache` 和 `sessionContainers`，被绕过后这些条目变成幽灵数据，永远不释放。

**当前代码**（`server/src/services/container-cleanup.ts:245-253`）：
```typescript
if (!options.dryRun) {
  for (const candidate of candidates) {
    const container = docker.getContainer(candidate.id);
    await container.remove({ force: true });   // ← 绕过了 removeContainer
    if (candidate.sessionId) {
      updateSessionEnvironment(candidate.sessionId, null, 'expired');
    }
    removed.push(candidate);
  }
}
```

**修改方案**：

从 container-manager 导出 cache 清理函数（因为 cleanup 不应该直接调用 removeContainer——它可能触发 stop 等不必要操作）：

```typescript
// container-manager.ts 新增导出
export function clearContainerCache(sessionId: string): void {
  sessionContainers.delete(sessionId);
  for (const [token, cachedSession] of sessionTokenCache.entries()) {
    if (cachedSession.sessionId === sessionId) {
      sessionTokenCache.delete(token);
    }
  }
}
```

然后在 cleanup 中调用：

```typescript
// container-cleanup.ts
import { clearContainerCache } from './container-manager.js';

// 在 container.remove() 之后添加：
if (candidate.sessionId) {
  clearContainerCache(candidate.sessionId);
  updateSessionEnvironment(candidate.sessionId, null, 'expired');
}
```

**验证**：
- `cd server && npx tsc --noEmit` 通过
- 手动验证：启动容器 → 等待 cleanup 触发 → 确认 sessionTokenCache 被清理

## 七、工作原则

1. **先读代码再改** — 每个任务开头列了必读文件，读完整文件再动手
2. **小步提交** — 每完成一个任务就 commit，不要攒大 PR
3. **不改无关代码** — 只改任务描述中涉及的文件，不顺手重构
4. **保持现有模式** — 代码风格、错误处理方式与现有代码保持一致
5. **不引入新依赖** — 除非绝对必要（GitHub OAuth 需要 `node-fetch` 或类似库除外）
6. **ESM 模块** — `import/export`，不用 `require`
7. **better-sqlite3 是同步 API** — 不需要 await，直接 `.prepare().get()`
