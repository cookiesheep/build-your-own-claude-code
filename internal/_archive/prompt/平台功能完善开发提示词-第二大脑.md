## 项目背景

**Build Your Own Claude Code (BYOCC)** 教学平台。学习者通过 6 个 Lab 逐步实现 Claude Code 的核心模块，最终将自己写的代码插入真实 Claude Code 系统运行。

### 当前平台状态（经代码验证）

| 组件 | 技术栈 | 实际状态 |
|------|--------|---------|
| 后端 | Express + SQLite + Docker + ttyd | **完整可用**：容器管理、代码注入、构建、WebSocket 代理 |
| 前端 | Next.js 16 + Monaco Editor + xterm.js | **完整可用**：Lab 布局、编辑器、终端、文件树 |
| 提交流程 | POST /api/submit | **100% 完成**：injectFiles → buildInContainer → 返回构建结果，线上已跑通 |
| 进度系统 | SQLite user_progress + /api/progress | **基础可用**：有表、有 API、有前端进度条，但状态太粗（只有 completed/not_started） |
| 文档面板 | DocsPanel | **完整可用**：读取 docs/labs/lab-NN/ 的 markdown，知识点/任务双 tab |

### 变体文件机制（已验证、Lab 0 在用）

学习者编辑的不是独立文件，而是带 `-labN` 后缀的**变体文件**，放在 claude-code-diy 源码的原始目录中：

```
/workspace/src/
  query.ts              ← 原始文件（不动）
  query-lab3.ts         ← Lab 3 变体（学习者编辑）

/workspace/src/components/LogoV2/
  Clawd.tsx             ← 原始文件（不动）
  Clawd-lab0.tsx        ← Lab 0 变体（学习者编辑）

build.mjs --lab=0
  → discoverLabSwaps() 发现所有 *-lab0.* 文件
  → 编译时替换原始文件的产物
  → 整个 416K 行系统一起编译
```

**⚠️ `labs/` 目录是空的，是废弃设计。学习者代码不在 `labs/` 下。**

### 提交后的 TUI 体验

Lab 0 实测行为：构建成功后，ttyd 终端自动显示完整 Claude Code TUI（ttyd 是容器 CMD，构建产物直接被加载）。只有某些 Lab（如需要 `node cli.js` 启动的）才需要手动操作。

## 已知的坑（踩过的）

1. **`labs/` 目录是空的** — 不要假设测试文件放在 `labs/lab-NN/tests/`
2. **`runExecCommand` 用 `Tty: true`** — 如果需要读 JSON，考虑用 `Tty: false` 的变体或文件输出
3. **`PlatformPageClient.tsx:25`** — `p.completed ? 'completed' : 'not_started'` 从来不映射 `in_progress`，是 bug
4. **`ProgressTracker.tsx`** — 从静态 `LABS` 数组读进度，不拿服务端数据
5. **`api.ts` ProgressResponse** — 只有 `{labNumber, completed}`，缺少 status 字段
6. **Docker 镜像没有 vitest** — 如果将来需要 vitest，必须先 `RUN npm install -D vitest`
7. **LabRightArea 568 行** — 加功能前考虑提取 hook
