## 核心设计决策

### 1. 测试在容器内执行，不是浏览器端

学习者的代码 import 了 `fs`、`child_process`、`path` 等 Node.js 模块，浏览器端根本跑不了。测试必须通过 `docker exec` 在容器内执行 `npx vitest run`。

**但有一个陷阱**：`runExecCommand`（`server/src/services/container-manager.ts:278`）使用 `Tty: true`，会把 ANSI 控制字符混入输出，破坏 JSON 解析。

**解决方案**：vitest 写 JSON 到文件，再单独读取文件：
```
# 第一次 exec：跑测试，结果写到文件
npx vitest run --reporter=json --outputFile=/tmp/vitest-results.json labs/lab-NN/

# 第二次 exec：读文件（没有 ANSI 污染）
cat /tmp/vitest-results.json
```

### 2. 容器里目前没有 vitest，也没有测试文件

Docker 镜像从 claude-code-diy 构建，它的 package.json 里没有 vitest。`build-lab-image.sh` 的白名单只拷贝 `src/` 和 `vendor/`，不包含 `labs/`。

**解决方案**：
- `Dockerfile.lab` 加 `RUN npm install -D vitest`
- `build-lab-image.sh` 和 `.ps1` 加 `labs/` 目录拷贝
- `Dockerfile.lab` 加 `COPY labs/ ./labs/`

### 3. TUI 不能自动启动

ttyd 是容器主进程（`CMD ["ttyd", "--writable", "--port", "7681", "/usr/local/bin/start-lab-shell"]`），有自己的 PTY。`docker exec` 启动的进程是独立的，学习者看不到。

**解决方案**：构建成功后在构建日志末尾追加提示消息：
```
========================================
  Build successful!
  Type: node cli.js
  and press Enter to start your Agent.
========================================
```

### 4. LabRightArea 568 行，必须先提取 hook

`platform/src/components/LabRightArea.tsx` 已经 568 行，直接加测试状态会爆到 700+ 行。必须先提取 `useTestRunner` hook，把测试相关状态和逻辑封装进去。

API 设计：
```
POST /api/test
Body: { sessionId: string, labNumber: number, files?: Record<string, string> }
Response: {
  success: boolean;
  results: Array<{ name: string; tests: Array<{
    name: string; status: "passed"|"failed"|"skipped";
```

4. 第二次 exec：`cat /tmp/vitest-results.json`（干净 JSON）
5. 解析 JSON 返回结构化结果
6. 超时 60 秒，返回部分结果
